# 공모취지 보강: 접근 제약과 AI 검토서 초안

작성일: 2026-10-18 (한국시간).

## 재현

Python 환경에 원래 requirements.txt의 의존성이 설치되어 있어야 한다.

```powershell
python data_28/analyze_accessibility.py
python data_28/build_review_drafts.py
python -m unittest discover -s data_28 -p test_revision.py -v
```

주 계산은 인터넷이나 AI API를 호출하지 않는다. `fetch_elevators.py`는 별도 선택 실행용 취득 코드다.

## 접근 제약 점검

입력은 `data_13/raw/osm_medium_windows_response.txt`다. 행사일 요청시점은 2026-04-04T22:00:00Z다. 원래 출입구 선택과 도로상 투영 시작점 22곳을 고정했다. 계단을 지운 뒤 출입구를 다른 연결망으로 옮기지 않았다. 기존 `PolicyEngine`의 안내 최적화는 이번 분석에서 다시 수행하지 않는다.

1. `highway=steps` 연결을 제외한다.
2. 추가로 `wheelchair=no`인 선형과 원본 지도 노드를 제외한다.
3. 출입구 자체의 `wheelchair=no`는 별도 분류한다. 도로상 투영 시작점이 연결되더라도 출입구의 제약을 지우지 않는다.
4. 태그가 없으면 `unknown`으로 기록한다.

서로 겹치지 않는 출입구 분류는 계단·제약 제외 후 새 경로 미산출 3곳, 출입구 자체 wheelchair=no 1곳, 기존 미연결 1곳, 경로가 남지만 접근성은 미검증인 17곳이다. 계단만 제외해도 같은 3곳이 새로 끊긴다. 출입구 태그는 yes 1곳·no 1곳·누락 20곳이다.

새 경로 미산출 출입구는 OSM ID 3390512293(서울역 1번출구 GTX-A), 3403067568(서울역 2번출구 공항철도역), 5348913429(원본명 출입구 1)이다. wheelchair=no는 3403067549(회현역 4번출구), 기존 미연결은 3390524793(서울역 9-1출구)다. 이름은 OSM 기록이며 시설 운영기관의 공식 명칭·현장 상태 인증이 아니다. 세부값·원본 링크는 `entrance_access_audit.csv`에 있다.

이 결과는 실제 접근 불가 인원·역 전체 접근 불가·엘리베이터 부재를 뜻하지 않는다. 대체 출입구, 보도, 턱, 경사, 횡단, 행사일 통제, 엘리베이터 가동, 휠체어 승차 차량은 확인하지 않았다. 기존 모형에는 일반도로 보행과 100m 이내 선형 투영 가정이 남는다. 해당 출입구를 사용하는 조건의 지도상 점검 결과로만 해석한다.

별도 과거 엘리베이터 요청은 DNS 오류로 실패했다(`raw/acquisition.json`). 원래 요청은 도로 선형·횡단·지하철 출입구와 재귀 골격 노드를 대상으로 해 독립 엘리베이터 위치 목록이 완전하지 않다. 따라서 결과 JSON의 0은 확보된 보조 목록의 수일 뿐 현장 설치 수가 아니다. 본문에는 설치 수를 제시하지 않았다.

## AI 역할과 검토서 생성

입력 `data_09/service_changes.json`은 과거 Codex 작업에서 공식 공지·노선도를 읽어 전사한 8800·M5107 2개 노선 기록이다. 이번 코드는 그 기록의 예정시간·정류소 ID·장소 유형·미확인 값 보존을 검사해 초안 2건을 생성한다. 통제시간과 노선별 예정시간도 다른 필드로 보존한다.

AI 전사와 규칙 기반 초안 생성은 서로 다른 단계다. 이번 Python 실행에 새 LLM 호출·OCR 엔진·자동 승인 기능은 없다. 전사 2건의 일관성 통과를 추출 정확도 100%라고 해석하지 않는다. 사람의 독립 정답표·현장 검수·시간절감 평가는 수행하지 않았다. 초안에는 출처와 원문 영역, 남은 확인 항목, 검토 상태가 포함된다.

`test_revision.py`의 6개 검사는 임시 장소 ID 조작, 시간 역전, 정류소 앞자리 0 소실, 접근성 미확인 값 조작을 거부하고, 서로 다른 시간 범위와 null을 보존하며, 계단 제거 때 출발점을 옮기거나 연결을 추가하지 않는지 확인한다.

## 프롬프트 기록

기존 실제 사용자 지시: “그거 이제 발전 시키자”, “공모전 취지에 맞게 발전시켜야됨” (`data_09/AI_활용기록.md`). 이번 실제 지시: “하위에이전트 하나 생성해서 의논해나가면서 공모전 기준에 맞게 수정해나가봐. 그리고 수정한 후에 재검토 및 평가해봐”. 서비스는 Codex 데스크톱이다. 모델 ID·설정은 검증하지 않아 기재하지 않는다.

재사용을 위한 제안 프롬프트(별도 모델에 실행한 원문 로그가 아님):

> 도로 통제시간과 노선 예정시간을 분리하고, 노선·미경유 정류소·임시 승차지마다 근거를 붙여라. 없는 ID·좌표·접근성은 null로 남겨라. 원문과 충돌하는 필드는 보류하고 담당자에게 확인 항목으로 전달하라.
